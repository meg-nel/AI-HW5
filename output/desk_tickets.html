3 · One agent instead of five

What would have been simpler as one agent with tools, and why?

  • Ticket 102 (rent) is the clearest case. One agent with get_lease, get_bills_and_cash, request_payment and draft_customer_message could do it in about five tool calls. The team needed 19 model calls and 23 tool calls, mostly hand-off overhead: the Boss wrote briefs, each specialist re-read the ticket, and wrote a report the Boss then re-read.
  • Ticket 101 is also simple sequential work: check stock, see the vendor block, pay the invoice, order the tee, draft the reply. There's no real parallel work and no step that needs a different expertise or model. A single agent would avoid passing the same facts through four briefs, where each hand-off is a chance to lose or restate a number.
  • Why one agent would be simpler here:
    • The rules don't depend on the agents. They're enforced in the MCP server: human approval, no negative cash, vendor block, drafts only. So the safety we get from splitting roles mostly comes from the tool layer, not from having five agents. A single agent behind the same server would be just as safe.
    • Lower cost and fewer moving parts. Fewer tokens (~240k across three small tickets) and one conversation to debug instead of five.
  • Where the team still earns its keep:
    • Least privilege per role: only Accounting can request money.
    • Shorter, focused prompts per job.
    • A natural fit for more tickets or different models per role, for example a cheaper model for Inventory lookups.
    For three small tickets, one agent with the same tools and the same approval gate would have been simpler.
